# Arc — мінімалістичний архіватор

Десктопний архіватор для Windows (Linux — пізніше). Еталон за можливостями — 7-Zip,
але з сучасним мінімалістичним інтерфейсом. Спілкування з користувачем — українською,
коментарі в коді та назви — англійською.

## Стек
- **Бекенд:** Rust, Tauri 2 (`app/src-tauri`).
- **Фронтенд:** Svelte 5 (руни) + SvelteKit `adapter-static` (SPA) + Vite, TypeScript, іконки `@lucide/svelte` (`app/src`).
- **Переклади:** `lang/en.json`, `lang/uk.json` (ключ → текст, `{}` — плейсхолдери), спільні для Rust і фронтенду.

## Еталон інтерфейсу — Tormin (`D:\GIT\Soft\Tormin`)
Інтерфейс, токени і компоненти беремо з Tormin і тримаємо в тому ж стилі:
- вікно без системної рамки (`decorations(false)`), Mica на Windows 11, власний заголовок `TitleBar.svelte`;
- **усі кнопки дій — у верхній панелі (заголовку вікна)**, порожнє місце тягне вікно (`data-tauri-drag-region`);
- дизайн-токени в `app.css` (`--bg`, `--surface*`, `--accent*`, `--radius`…), темна тема за замовчуванням, `html[data-theme="light"]`;
- **акцентні кольори:** пресети purple/green/orange/blue + власний `#rrggbb` (через `fitAccent()` в `accent.ts`, що підтягує контраст) + «system» (акцент Windows із реєстру DWM);
- спільні компоненти: `Menu`, `Modal`, `Select`, `Dialogs` (черга діалогів у `store.svelte.ts` через `openDialog(kind, props)`), `Settings`.
Перш ніж робити новий елемент UI, подивись, як подібне зроблено в Tormin.

## Функціональність
| Формат | Створення | Розпакування | Пароль |
|---|---|---|---|
| .zip | `zip` | `zip` | AES-256 (читання також ZipCrypto) |
| .7z | `sevenz-rust2` (LZMA2) | `sevenz-rust2` | AES-256, опційно шифрування назв |
| .tar.gz / .tgz | `tar` + `flate2` (zlib-rs) | те саме | — (формат не підтримує) |
| .tar.xz | `tar` + `liblzma` (static, parallel) | те саме | — |
| .rar | — (ліцензія UnRAR забороняє) | `unrar` | так |

- Головне вікно — **браузер архіву** як у 7-Zip: навігація по папках усередині архіву, відкриття окремого файлу подвійним кліком без розпакування всього архіву (файл розпаковується в `%TEMP%\Arc\…` і відкривається програмою за замовчуванням), розпакування вибраних елементів.
- Drag-and-Drop у вікно: архів → відкрити; інші файли/папки → вікно створення архіву.
- Drag-and-Drop **з архіву** в Провідник (як у 7-Zip, `dragout.rs`, лише Windows): зсув миші ≥6 px від натиснутого рядка → `drag_out` у головному потоці створює порожні заглушки вибраних елементів у `%TEMP%\Arc\drag-*` і одразу запускає `SHDoDragDrop` з власним `IDropSource`. Розпакування (лише потрібних записів, з ранньою зупинкою для solid 7z/tar/rar через `expected_files`) відбувається в `QueryContinueDrag` при відпусканні кнопки над ціллю, що приймає файли (не над вікном Arc), — тому перетягування починається миттєво навіть для solid-архівів. Поки розпаковується, вікно качає повідомлення без вводу (інакше OLE повторно входить у `QueryContinueDrag`), показує прогрес у рядку стану, Esc скасовує. На інших ОС — старий шлях (крейт `drag`, розпакування до початку). Натискання на вже виділений рядок не скидає виділення, тож можна тягнути кілька. Поки йде перетягування, `app.draggingOut` змушує вікно ігнорувати власний drop. Зашифровані: пароль питається до перетягування.
- Операції (jobs) виконуються у фонових потоках; прогрес надсилається подією не частіше ~7 разів/с; кожну можна поставити на паузу (`Progress::check` чекає) і скасувати. ZIP розпаковується паралельно (до 8 потоків, у кожного свій дескриптор архіву, черга записів від найбільших).
- **Архівація і розпакування завжди йдуть в окремому маленькому вікні операції** (`task-N`, `TaskWindow.svelte`): форма створення → прогрес із кнопками Пауза/Скасувати → саме закривається; пароль питається в ньому ж; помилки показує в кінці. Користувач прямо відмовився від панелі операцій унизу головного вікна — не повертати. Розмір вікна підлаштовується під вміст (ResizeObserver → `setSize`). Головне вікно лише відкриває архів і окремі файли з нього (індикатор у рядку стану).
- Вікна операцій і головне — та сама сторінка `+page.svelte`, гілка за міткою вікна. Arc завершується з останнім вікном; закриття головного не зупиняє операції.
- Імена в старих ZIP без прапорця UTF-8: системна OEM-сторінка, якщо вона кирилична (866/1125); інакше евристика — серія ≥3 байтів у кириличних діапазонах CP866 або кирилична локаль → CP866, а байти 0xF6–0xF9 → CP1125 (українська Windows); інакше CP437. У користувача англійська Windows (OEMCP=437), тому на системну сторінку покладатися не можна.
- Обов'язковий захист від zip-slip: імена записів проходять через безпечне з'єднання шляхів (без `..`, коренів, дисків).
- Помилки пароля передаються фронтенду кодами `password_required` / `wrong_password` — фронтенд питає пароль і повторює операцію.

## Асоціації файлів (Налаштування → Windows)
- `register_app` при кожному запуску: ProgID `Arc.Archive`, OpenWithProgids, `Software\Arc\Capabilities` + `RegisteredApplications` (сторінка Arc у «Програмах за замовчуванням»). Не залежить від перемикача контекстного меню.
- Кнопка «Зробити за замовчуванням» (`associate`): класові значення `.ext → Arc.Archive` і, якщо якийсь тип ще не Arc, відкриває `ms-settings:defaultapps?registeredAppUser=Arc`. Стан кожного розширення — `AssocQueryString(ASSOCSTR_PROGID)`; оновлюється, коли вікно знову отримує фокус.
- **Перевірено на машині користувача:** Windows 10/11 Explorer слухає лише `UserChoice`/`UserChoiceLatest` (у Win11 ProgId — у вкладеному ключі `UserChoiceLatest\ProgId`), записати їх може тільки Windows (хеш + UCPD). Видалення чужого вибору НЕ робить Arc типовим, а лишає тип без програми — тому вибір користувача ніколи не чіпаємо. Злом хешу (SetUserFTA) — ні. На цій збірці Windows кнопки «Set default для всіх» немає: користувач вибирає Arc біля кожного типу.

## Контекстне меню Explorer (як у 7-Zip)
Реєстр `HKCU\Software\Classes` (без прав адміністратора), каскадне меню «Arc»:
Архівувати · Запаролити · Розархівувати · Розархівувати в папку.
- **Нове меню Windows 11** — COM-обробник `IExplorerCommand` (`app/shellext`, крейт `arc_shell`, cdylib зі статичним CRT, CLSID `37B70A45-F2C2-4F46-8A59-3EE158D32A3D`) + розріджений (sparse) MSIX-пакет `src-tauri/msix/AppxManifest.xml` (ідентичність `Arc.Archiver`, `CN=Arc Archiver`, external location = папка встановлення). Збирає `app/scripts/build-shell.ps1` (його викликає `dev.ps1`) у `src-tauri/shell/` (gitignore; ресурси в `tauri.windows.conf.json`, без них `cargo check` падає): DLL, `Arc.msix` (логотипи всіх розмірів, включно з `targetsize-*`/`altform-unplated`, генеруються з `icons/icon.png` + `resources.pri` через makepri — інакше Settings показує стандартну іконку), підписаний власним self-signed сертифікатом із `Cert:\CurrentUser\My` (створюється при першій збірці, приватний ключ нікуди не виходить), і `arc.cer`.
- Інсталятор (`installer-hooks.nsh`) запускає `register-shell.ps1`: один раз через UAC додає `arc.cer` у `LocalMachine\TrustedPeople`, `Add-AppxPackage -ExternalLocation`, ставить `HKCU\Software\Arc\Menu\Packaged=1` і прибирає класичні дієслова (Windows 11 показує пакетне меню і в «Показати більше параметрів» — інакше було б два «Arc»). Журнал: `%LOCALAPPDATA%\Arc\shell-install.log`. На Windows 10 пакет не ставиться — лишаються дієслова реєстру. Завантажену DLL не можна перезаписати — хуки перейменовують її (`arc_shell-old-*.dll`).
- **Перевірено на машині користувача (Windows 11 26H2, KB5127936):** сторонні пункти нового меню за замовчуванням вимкнені — користувач вмикає Arc у налаштуваннях кастомізації контекстного меню (розділ App Extensions). До цього Explorer викликає обробник (видно в журналі), але пункт не показує. Нічого в пакеті це не лагодить.
- Стандартний «Compress to» — `CLSID_CompressToCommand` `{7AE6900F-6EB0-44A2-9CA1-DB2F7EF352AF}`; ховається значенням у `HKCU\Software\Microsoft\Windows\CurrentVersion\Shell Extensions\Blocked` + перезапуск Explorer (без прав адміністратора).
- DLL читає `HKCU\Software\Arc\Menu` (пише `shell::register`): `Exe`, `Enabled` (вимикач у налаштуваннях), заголовки пунктів, `Extensions` (пункти розпакування — лише якщо всі вибрані файли архіви). Виклик: усі шляхи у `%TEMP%\arc-menu-*.txt` → `arc.exe --<дія> --list <файл>` (Arc читає й видаляє лише файли з таким ім'ям); такий запуск одразу йде в окреме вікно операції, без `menubatch`.
- Пункти розпакування показуються лише для архівних розширень (`AppliesTo`), `MultiSelectModel=Player`.
- При виборі кількох файлів Explorer запускає процес на кожен файл, по черзі. Їх зливає `menubatch.rs` **ще до старту Tauri**: кожен процес під named mutex дописує свої шляхи в `%LOCALAPPDATA%\Arc\menu-<action>.txt`; перший (збирач) чекає, доки 1 с не з'являється нових, забирає все; решта одразу виходять. Пачка виконується в окремому процесі без single-instance (не залежить від відкритого головного вікна). Старий спосіб (пересилання через single-instance + таймер 450 мс) губив файли: таймер стартував раніше, ніж перший екземпляр міг приймати повідомлення. Одна архівація всіх файлів; «в папку» — кожен архів у свою папку з назвою архіву.
- «В папку» — **завжди** папка з назвою архіву (вимога користувача); подвійна вкладеність прибирається лише коли всередині одна папка з тією ж назвою (`foo.zip` з `foo\` → `foo\…`).
- Запуск із меню (будь-яка дія, крім open) **не створює головне вікно**: одна пачка запитів = одне вікно операції; після успіху воно закривається, і якщо інших вікон немає — Arc завершується.
- Пункти меню реєструються як `*\shell\Arc` + `Directory\shell\Arc` (пакування) і `SystemFileAssociations\.<ext>\shell\Arc` (повне меню): однакове ім'я дієслова, тож Explorer показує для архівів лише специфічне.
- Аргументи командного рядка: `--add`, `--add-password`, `--extract-here`, `--extract-folder`, без ключа — відкрити архів.
- Ключі реєструються при запуску (якщо увімкнено в налаштуваннях) і видаляються NSIS-хуком при деінсталяції.

## Структура
```
lang/                 переклади en/uk
app/src/              фронтенд (routes/+page.svelte, lib/api.ts, lib/store.svelte.ts, lib/components/*)
app/src-tauri/src/    lib.rs (команди, стан, single-instance), config.rs, jobs.rs,
                      archive/ (mod.rs — спільні типи і детект формату; zip.rs, sevenz.rs, tar.rs, rar.rs),
                      shell.rs (контекстне меню, системний акцент)
```

## Збірка та перевірка
- Розробка: `app\dev.ps1` (або `npm run tauri dev` у `app`), інсталятор: `app\dev.ps1 -Build` (NSIS). `run.bat` у корені: 1 — dev, 2 — інсталятор NSIS (користувач тестує UI сам через нього; мишею/клавіатурою не керувати).
- Із Bash-інструменту `npm run tauri dev` не бачить cargo: запускати з PowerShell з `$env:Path = "$env:USERPROFILE\.cargo\bin;$env:Path"` і `cmd /c "npm run tauri dev > log 2>&1"` (dev.ps1 з перенаправленням падає через `ErrorActionPreference=Stop` на stderr npm).
- UI перевіряється знімками вікна (скрипти shot/click/type у scratchpad). У системі не англійська розкладка: `SendKeys` вводить сміття — текст вводити через буфер обміну + `keybd_event` (VK-коди).
- Процеси, запущені з пісочниці інструментів, не можуть писати в `%APPDATA%`/`%LOCALAPPDATA%` (конфіг і лог мовчки не зберігаються) — це не баг Arc; перевіряти збереження з `dangerouslyDisableSandbox`.
- Гарячі клавіші WebView2 (пошук F3/Ctrl+F, друк тощо) блокуються в `+page.svelte` (`blockBrowserKeys`, capture-фаза) — у Tauri немає прапорця для цього.
- Перевірки: `cargo check` / `cargo test` у `app/src-tauri`, `npm run check` у `app`.
- `unrar` і `liblzma` компілюють C/C++ — потрібен MSVC (є).
- Конфіг користувача: `%APPDATA%\Arc\config.json`, лог: `%LOCALAPPDATA%\Arc\arc.log`.
